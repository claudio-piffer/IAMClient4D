# JWT Validator and JWKS Provider Test

Console program that checks `TIAM4DJWTValidator` and `TIAM4DJWKSProvider` against a fake identity provider: an Indy HTTP server on `127.0.0.1:18781` serves OIDC discovery and JWKS for any `/realms/<name>` and counts the requests per path. No real identity provider is needed.

Tokens and keys come from `JWTTestVectorsU.pas`, generated by `gen_tokens.py`: two RSA-2048 keys and RS256 tokens issued by `http://127.0.0.1:18781/realms/test` that expire in 2099. Tokens that fail before the signature check (random `kid`, other issuers, `alg` none) are built by the test.

## What it checks

| Area | Checks |
|------|--------|
| Valid token | RS256 token accepted with its claims; one discovery and one JWKS request, then the key cache; tampered signature rejected |
| Token format | Empty token, 2 or 4 parts, header not JSON, header `typ` missing or not `JWT`, `crit` header, padding, characters outside base64url or unused bits set in the last character rejected; payload `typ` checked against the expected token type (`ID` refused where `Bearer` is expected, no `typ` accepted); `SetAllowedHeaderTypes`: `JWT` still accepted with `at+jwt`, `at+jwt` and `application/AT+JWT` pass the `typ` check, `dpop+jwt` refused, only `at+jwt`: `JWT` refused, empty list refused |
| `alg` | Case-sensitive allow-list (RFC 7515): a validly signed token with `alg` `rs256` is rejected, also with the allow-list `[RS256]`; `none` rejected in any case |
| Issuer | Expected issuer empty or `/`: every token rejected without requests to the identity provider (the token `iss` is never used for discovery); a token of another issuer rejected without requests |
| Unknown `kid` storm | 200 tokens with random `kid`: at most one discovery and one JWKS request, at most one negative cache entry, the known key still accepted |
| Parallel storm | 16 threads, cold start with a slow JWKS endpoint: valid tokens accepted, random `kid` rejected, one discovery and one JWKS request |
| Refresh interval | Key rotation: a new `kid` is rejected without requests within the interval and accepted after it; discovery cached |
| Negative cache | Without refresh interval, 50 random `kid`: one JWKS request each (no second fetch), negative cache capped by `SetMaxNegativeKidEntries` |
| Identity provider failing | Expired key served while the JWKS endpoint fails, no retry within the interval; with the endpoint back and slow, parallel requests use the expired key while one refresh runs; stale while revalidate: an expired key is served without waiting for a slow JWKS endpoint, one background refresh, fresh key afterwards, a withdrawn `kid` refused once the refresh ends |
| Signing keys only | A key with `"use":"enc"` listed first is skipped for a token without `kid`; a key with a matching `kid` and `"use":"enc"`, or `key_ops` without `verify`, is not used; `key_ops` with `verify` is |
| Shared `kid` | An EC and an RSA key with the same `kid` (RFC 7517 4.5): an RS256 token gets the RSA key, after the refresh and from the cache; with the EC key alone it is rejected |
| Key `alg` | Same RSA key: with `alg` `RS256` or no `alg` it verifies the RS256 token; with `PS256`, `rs256` or a non-string `alg` the token is rejected |
| Discovery issuer | A discovery document with another `issuer`, or none, is rejected without JWKS requests (OpenID Connect Discovery 1.0 4.3); a trailing `/` is accepted |
| Identity provider unavailable | JWKS endpoint failing or wrong discovery issuer: `EIAM4DJWKSUnavailableException` with `RetryAfterSeconds` (refresh interval, then the remaining seconds); an unknown `kid` with the identity provider up stays a token error |
| JWKS URI | `SetJWKSUri`: keys fetched from the configured URL without discovery, kept by `ClearCache`; an empty URI restores discovery |
| Issuer isolation | One provider, two issuers: a slow JWKS endpoint of one does not delay the other |
| Token cache | Cache hits return claims owned by the caller; concurrent hits; eviction with one entry; a cached token is validated again after `SetExpectedAzp` and `SetAllowedAlgs`, and rejected once older than the `SetIatMaxAge` limit |
| jti replay | `SetJtiValidation`: token without `jti` rejected, the same token rejected the second time (token cache on), 8 parallel requests with one token: one accepted, in 20 rounds |
| Time claims | `exp` missing, not a number or a numeric string rejected; `exp`, `nbf`, `iat` with a fraction handled (a fractional `nbf` ahead is not ignored); clock skew 60 s: `exp` 30 s ago accepted, 120 s ago rejected; `nbf` and `iat` 30 s ahead accepted, 120 s ahead rejected; `iat` required and checked against the max age when `SetIatMaxAge` is set |
| Error codes | Expired token `ecJWTExpired`, `nbf` ahead `ecJWTNotYetValid`, another audience, no expected audience in an array, no `aud`: `ecJWTAudienceMismatch`; another issuer `ecJWTIssuerMismatch` |
| `aud` and `azp` | Expected audience accepted, others and case variants rejected; array rules with `azp` (OIDC Core 3.1.3.7); expected `azp`; audience validation off; an empty expected audience with the check on is a configuration error and never matches an `aud` `""` element |

The parallel tests use a verifier that checks the key identity instead of the RSA signature: they test the JWKS provider, not the crypto provider.

## Run

From a command prompt (RAD Studio 13, Win64 by default):

```bat
tests\JWT\run_tests.bat
tests\JWT\run_tests.bat Win32
tests\JWT\run_tests.bat Linux64
```

`Linux64` runs through WSL (`libcurl` required by `THTTPClient`); without WSL the script only builds. Exit code: number of failed checks (`0` = all passed, `99` = the fake identity provider cannot listen on port 18781). Memory leaks are reported on stderr (Windows). Build output goes to `tests/bin` and `tests/dcu`.

To regenerate the keys and tokens (Python 3, standard library only):

```bat
python tests\JWT\gen_tokens.py
```

# Keycloak Client Login Flow Test

Console program that runs the login flows of `TIAM4DKeycloakClient` (Authorization Code with PKCE, password grant) against a fake identity provider: an Indy HTTP server on `127.0.0.1` (free port chosen by the system) serves OIDC discovery, the authorization endpoint (302 to `redirect_uri` with `code` and `state`), the token endpoint (tokens with an `id_token` signed RS256 carrying the nonce of the request; optionally slow or failing; password and refresh token grants with Keycloak's error answers), the JWKS endpoint (`jwks_uri` of the discovery) and the end session endpoint. The signing key is generated at startup by `TestRSASignerU` (RSA 2048 through CNG, `bcrypt.dll`, on Windows and through OpenSSL `libcrypto.so.3` on Linux): the client validates the id_tokens as it does with Keycloak. No browser and no Keycloak are needed.

The browser is replaced through `TIAM4DPlatformUtils.OpenURLHandler`, assigned before any flow starts: a thread GETs the authorization URL and follows the redirect to the local callback server of the client. The handler refuses every URL that is not the authorization endpoint of the fake identity provider, and stays assigned (refusing everything) until the program ends: the real browser is never opened.

## What it checks

| Area | Checks |
|------|--------|
| `OpenURLHandler` | `OpenURL` calls the handler with the URL unchanged and returns its result; an exception of the handler gives `False`; `file:`, `javascript:`, `data:`, no scheme and empty never reach it |
| Login | `OnSuccess` and `OnFinally` once, access token of the exchanged code, `IsAuthenticated`; authorization request: `response_type`, `client_id`, loopback `redirect_uri`, `openid` scope, `state` and `nonce` (32 hex digits), `code_challenge` (43 base64url characters) with `S256`; token request: `grant_type`, `code`, same `redirect_uri`, `code_verifier` (RFC 7636 characters and length) whose SHA-256 is the `code_challenge`; callback server stopped afterwards; a second login gets new state, nonce and PKCE pair |
| `kc_idp_hint` | In the login and in `GenerateAuthURL`: none configured, per-login alias, configured alias, per-login alias over the configured one, blank argument, `IAM4D_IDP_HINT_NONE` (no hint even with a configured alias, also as configured value) |
| Encoding | `GenerateAuthURL` with `login_hint`, `kc_idp_hint`, scopes and `acr_values` containing space, `&`, `=`, `+`, `/`, `%`, non-ASCII characters and an emoji, and an external `redirect_uri` with its own query: strict `application/x-www-form-urlencoded` parsing, each parameter once and decoded to the original value; same for the URL handed to the browser by `StartAuthorizationFlowAsync` |
| External callback | `InitializeAuthorizationFlow` + `GenerateAuthURL` + `CompleteAuthorizationFlow`: wrong state raises `EIAM4DStateMismatchException` without a token request; the right one returns the access token, PKCE verified |
| Errors | Token endpoint 400 (`invalid_grant`), nonce mismatch in the `id_token` (`ecNonceValidationFailed`): `OnError` and `OnFinally` once, `EIAM4DException`, operation faulted, not authenticated, callback server stopped; browser that cannot be opened: `StartAuthorizationFlowAsync` raises, the client stays usable; discovery of an unknown realm (404): `Build` raises `EIAM4DDiscoveryFailedException` (`ecDiscoveryFailed`) naming the URL and the status |
| Error responses | `error=access_denied` with the state of the flow: `OnError` with `EIAM4DOAuth2CallbackException` (`error` and `error_description` in its `Context`), no token request, callback server stopped, 400 page with the description HTML-escaped; the same error with another state or without state, and a code with another state, are ignored: error page reflecting nothing, the login keeps waiting and the real callback still completes it |
| Cancellation | `Cancel` and `CancelAuthorizationFlow` while waiting for the browser, client released while waiting, a second login cancelling the first, `Cancel` and client release while the code is exchanged (slow token endpoint: the promise ends cancelled once, the late tokens are discarded, the destructor waits for the exchange), `Cancel` after the login completed (no effect) |
| Stop while accepting | 40 rounds of a connection to the callback server immediately followed by `Cancel`: every login ends cancelled once. Indy used to hang there in `TIdScheduler.TerminateAllYarns` (see `TIAM4DCallbackServerScheduler` in `IAMClient4D.Server.Callback.IndyHttpServer`) |
| Stop with an idle connection | 5 rounds of `CancelAuthorizationFlow` with an idle connection open (like a browser preconnect): every login ends cancelled once, median `Stop` at most 250 ms (Indy's `TerminateAllYarns` alone waits 500 ms) |
| Password grant | `AuthenticatePassword` (sync and async): access token, `IsAuthenticated`, `GetAccessToken`, no authorization request; token request: `grant_type=password`, `client_id`, `username`, `password` with `&`, `=`, `+`, `%`, space and non-ASCII encoded, `openid` scope, no PKCE nor `redirect_uri`, `client_secret` only for a confidential client |
| Password grant errors | Keycloak answers mapped to `EIAM4DInvalidCredentialsException` (wrong password, unknown user, empty username without request), `EIAM4DAccountNotFullySetUpException` (`ecAccountNotFullySetUp`), `EIAM4DAccountDisabledException`; `unauthorized_client` as a plain `EIAM4DException` with the answer; a failed login keeps the previous session; an Authorization Code client refuses it |
| Authorization Code logout | `Logout` after a login POSTs the refresh token of the session to the end session endpoint |
| Password refresh and logout | Expired access token refreshed with the refresh token of the login; `Logout` POSTs the refresh token of the session to the end session endpoint (204), nothing without a session, login again afterwards |
| Authorization request options | `prompt` and `max_age` absent by default, sent once with `WithPrompt(IAM4D_PROMPT_LOGIN)` and `WithMaxAge(0)` and kept by later `With*` calls; `login_hint` and `kc_idp_hint` of `StartAuthorizationFlowAsync(AIdpHint, ALoginHint)` |
| `auth_time` with `max_age` | `max_age=0`: fresh `auth_time` and one within `IAM4D_AUTH_TIME_CLOCK_SKEW_SECONDS` accepted; no `auth_time` or an hour old (SSO session reused): `EIAM4DSecurityValidationException` with `max_age` in `Context`, tokens discarded; `max_age=3600`/`600` with an authentication 30 minutes old: accepted/refused; without `max_age` no check; `CompleteAuthorizationFlow` (external callback) refuses an old `auth_time` |
| Fixed callback port | `WithCallbackPort`: the login completes with `redirect_uri` on that port |
| App redirect (`cbmAppRedirect`) | `IsValidRedirectURI` (valid and invalid schemes and paths, `http(s)`, query, fragment, empty labels) and the builder errors (`EInvalidOpException`, `EArgumentException`); `scheme:/path` parsing (encoded code and state, `error` with its description, fragment, `session_state` and `iss`, `scheme://`, `http` unchanged, malformed URLs); login with a fake browser that GETs the authorization URL without following the redirect and hands its `Location` to `TIAM4DAppRedirect.HandleURL`: exact `redirect_uri` in the authorization and token requests, PKCE, the redirect taken once (a replay returns `False`, four concurrent deliveries make one token request); `access_denied`; forged redirects (other state, no state, other scheme or path, `http`, malformed, empty) ignored and the real one then completes the login; `Cancel`, `CancelAuthorizationFlow`, client released and a second login while waiting; no login waiting; two clients with the same redirect URI told apart by the state; `cbmExternal` still refuses `StartAuthorizationFlowAsync` |
| Builder | `ForPassword` keeps grant type and secret through `WithScopes`, `WithTimeouts`, SSL and expiry buffer; `WithPrompt`, `WithMaxAge`, `WithCallbackPort`, `WithIdentityProvider` refused; Authorization Code keeps prompt, max_age, port, secret and hint; a second `For*` inherits neither identity provider nor ACR values |
| Refresh errors | Refresh refused (`invalid_grant` "Session not active"): `EIAM4DRefreshTokenExpiredException` with the reason in `Context`, tokens cleared; server error (500) and response timeout: tokens kept, `IsAuthenticated`, the next call refreshes |
| Logout errors | `invalid_grant` at logout: no exception; server error: `EIAM4DException`, tokens cleared anyway; refresh token already expired: no request |
| Scopes after logout | The configured scopes are sent again by the login after a `Logout` |
| Password login again | A second login ends the first session (its refresh token posted to the end session endpoint); a failure ending it does not stop the login; a failed login ends nothing |
| Discovery cache | One discovery request for several clients of a realm, cached endpoints usable; pinned keys and another SSL mode fetch their own; failed discovery not stored; disabled cache and expired entries fetch again |
| id_token in the login | Signed RS256 with one audience, and with several audiences and `azp`: accepted. Altered signature, unknown `kid`, `alg` `none`, other issuer, audience without the client, several audiences without `azp`, `azp` of another client, expired (beyond the 300 s tolerance), `iat` in the future: `OnError` and `OnFinally` once, `EIAM4DSecurityValidationException` with the code of the check (`ecJWTSignatureInvalid`, `ecJWKSKeyNotFound`, `ecJWTIssuerMismatch`, `ecJWTAudienceMismatch`, `ecJWTExpired`, `ecNonceValidationFailed`, otherwise `ecTokenInvalid`), the reason in the message and not the token, operation faulted, one token request, tokens discarded, callback server stopped |
| id_token keys | Keys from the `jwks_uri` of the discovery, fetched once for two logins of the same client, no second discovery request; three new clients reuse the keys of the process (`TIAM4DSharedJWKSProviders`, one provider), with sharing disabled a new client downloads them |
| id_token: external callback and password grant | `CompleteAuthorizationFlow` with an altered signature refused (tokens discarded); password grant with another issuer refused (not authenticated); a second password login with an expired id_token refused, the previous session kept and not ended |
| id_token on refresh | Authorization Code and password: refresh accepted with the same `sub`, `aud` and `nonce`; refused, tokens cleared: other `sub`, other `aud`, a `nonce` after a login without one, altered signature, other `nonce` and other `sub` after an Authorization Code login |
| `SecureZeroStrings` | List cleared; a line shared with another variable is not overwritten |
| Redirects not followed | A 307 of the token endpoint fails the login with a message naming the `Location`; one token request, no second POST of the form |
| Plain HTTP | `IsInsecureHTTPURL`: loopback names and IPv4 literals accepted, LAN hosts, `localhost.example.com` and `127.0.0.1.example.com` refused; `BaseURL` and external callback over `http://` refused without `WithAllowInsecureHTTP`, accepted with it (kept by later builder calls) |
| `iss` (RFC 9207) | Local callback: `iss` of the issuer accepted, of another issuer refused (no token request), missing refused only when the discovery announces it; external callback: `CompleteAuthorizationFlow(Code, State, Iss)` refuses another issuer, accepts the issuer and a missing `iss` |
| Refresh after a new login | A refresh answered after a second login does not overwrite its tokens; the refreshing call returns the token of the new login |
| Options of one login | `TIAM4DAuthRequestOptions`: invalid `prompt` (unknown value, `none` with another), `max_age` below `IAM4D_MAX_AGE_CONFIGURED`, `acr_values`/`ui_locales` with a space or empty, reserved parameters in any case and names with `&` refused; `acr_values`, `prompt`, `max_age`, `ui_locales` and a custom parameter (last value wins) replace the configured ones, `login_hint` of `GenerateAuthURL` added, a new flow without options is back to the configuration; `auth_time` checked against the `max_age` of the login (local callback and `GenerateAuthURL(AOptions)` with the external callback), a consumed state not brought back |
| Authorized HTTP client | `TIAM4DAuthorizedHTTPClient` on a local API: bearer of the client without a token request; 401 to a valid token: one renewal, request sent again, session kept; POST body sent again unchanged; a second 401 returned (one retry), `RetryOnUnauthorized` off; 302 not followed; `Authorization` in the headers, plain HTTP to another host and a non-HTTP URL refused before sending; `InvalidateAccessToken` of another token does nothing; 8 threads getting 401 for the same token: all 200, one renewal |
| Revocation and logout URL | `RevokeTokens`: refresh token then access token with `client_id`, tokens cleared, no logout request, nothing sent without tokens; `unsupported_token_type` for the access token accepted; 500: `EIAM4DException`, tokens cleared anyway. `GenerateLogoutURL`: end session endpoint, `client_id`, `id_token_hint`, encoded `post_logout_redirect_uri`, `state`, no request; plain HTTP to the loopback accepted, to another host and other schemes refused; without tokens no `id_token_hint` |
| id_token claims and granted scopes | `GetIDTokenClaims` empty before the login and after `Logout`; `sub`, `iss`, `aud`, `azp`, `acr`, `amr`, `sid`, `auth_time`, `iat`/`exp`, `preferred_username`, `email`, `name`, an object claim as JSON, `HasClaim`; `GetGrantedScopes` from the token response, `HasGrantedScope` case-sensitive; a refresh without `scope` keeps them, its id_token is read; no `scope` in the answer: the requested scopes; `FromIDToken` of a malformed token raises |

A watchdog reports a test that does not end within 90 seconds as hung and exits with code `98`.

## Run

From a command prompt (RAD Studio 13, Win64 by default):

```bat
tests\KeycloakClient\run_tests.bat
tests\KeycloakClient\run_tests.bat Win32
tests\KeycloakClient\run_tests.bat Linux64
```

`Linux64` runs through WSL (`libcurl` required by `THTTPClient`); without WSL the script only builds. Exit code: number of failed checks (`0` = all passed, `98` = a test hung, `99` = the fake identity provider cannot start). Memory leaks are reported on stderr (Windows). Build output goes to `tests/bin` and `tests/dcu`.
